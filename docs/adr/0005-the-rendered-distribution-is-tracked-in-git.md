# The rendered distribution is tracked in git

`dist/` was gitignored, which left the repository with no way to prove that the committed skill and agent trees match a fresh render: on an ignored, untracked directory a bare `git diff --exit-code -- dist/` always passes. From the ZCode adapter onwards the rendered output of every harness is tracked and committed with its source, and the gate is `test -z "$(git status --porcelain -- dist/)"`, which fails whenever the tracked tree and a fresh render diverge. A bare `git diff --exit-code -- dist/` is not the gate: it cannot see untracked additions, so a render that creates a new rendered file would pass it silently.

## Considered options

- **Keep `dist/` ignored and force-stage it** (`git add -f dist/` plus `git diff --cached --exit-code`): keeps the tree smaller, but the gate depends on a step a contributor can forget, and the ignore rule still fights every normal git command.
- **Re-render into a scratch tree and compare**: proves the same thing without committing generated files, but leaves consumers with no installable distribution in the repository, which is what `install.sh` reads.
- **Track `dist/`** (chosen): generated files appear in diffs and reviews, which is the cost, but the distribution is installable straight from a clone and any divergence between source and render — tracked or untracked — shows up as a dirty tree, which the status gate above fails on. The gate is conditional on how the render is run: the render embeds install paths and model overrides read from the environment, so the tracked distribution is the one produced in the canonical render environment of FR-018 (every harness home variable unset, the factory configuration home pointed at a path holding no `config.json`), and a non-canonical local render or install must be reverted with `git checkout -- dist/`, or re-rendered canonically, before the check is trusted.
