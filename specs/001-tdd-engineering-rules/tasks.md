# Tasks: Engineering discipline for factory code-writing roles

**Input**: Design documents from `/specs/001-tdd-engineering-rules/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: No test tasks. `plan.md` ("Test seams") declares **the whole change documentation/configuration-exempt from test-first** (FR-025): every task below edits a Markdown instruction file or regenerates the per-harness copy of one, so there is no seam, no entry point and no test runner. Verification is `commands.build` (render every harness) plus `commands.test` (`git diff --exit-code -- dist/`) plus the inspection checks of [quickstart.md](./quickstart.md). Every task names that exemption **in its task text, pointing at the plan**; an exempt task's commit body carries no `Red:` line and no substitute wording (ENG-2, ENG-5, [contracts/commit-body.md](./contracts/commit-body.md) "Placement"), so nothing is skipped silently (FR-012).

**Coverage note**: FR-025 has no task of its own because `plan.md`'s "Test seams" section already satisfies it; it is verified by T001 (baseline), T012 (`dist/` drift check) and T016 (deferred end-to-end observation). SC-003a likewise has two legs and no task of its own for the first: this plan's "Reasons for new files, abstractions and dependencies" section is the worked example, inspected in T013 (quickstart step 10), while the instruction that makes every future plan carry it is T006 and the end-to-end observation is T016.

**Rendering**: every task that edits `core/` re-renders all four harnesses and commits the regenerated `dist/` in that task's own commit, so no commit in this run's history carries a stale `dist/` (constitution III, FR-023). One render writes all four harness trees, so no two `core/`-editing tasks run in parallel.

**Organization**: Tasks are grouped by user story. Phase 2 is foundational on purpose: `DESIGN.md` must lead (constitution I, FR-022) and the shared reference must exist before any role can point at it (FR-001, FR-004).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (US1..US4)
- Paths are repository-root-relative inside the worktree

## Path Conventions

Source lives in `core/` (harness-neutral) and `adapters/`; `dist/<harness>/` is generated by `tools/render.py`. **Never hand-edit anything under `dist/`** (constitution III). No `src/` or `tests/` tree exists in this repository and none is created.
