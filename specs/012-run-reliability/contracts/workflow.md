# Workflow Contract

## Setup boundary

Before new run resources and after relevant resume setup changes, inspect effective selected models using the adapter's actual capability. Preserve exact IDs and evidence. A definite active-setup rejection blocks with correction/recheck instructions. Unsupported, errored, partial or unresolved inspection is unverified. Later rejection retains original diagnostic and existing bounded retry/halt. No silent substitution or credential changes.

## Tasks and resume

New behavior tasks contain ordered red, implementation, passing verification and one commit. Test and implementation are one completion unit. A legacy adjacent pair is one unit only when unambiguous; partially checked legacy pairs are inspected and reconciled with git/worktree evidence, never blindly repeated or treated as finished. Ambiguity returns through the orchestrator before code changes.

## Scope gate

Declarations name seams and covered injected failures; protected confirmation separately accepts exactly that scope. Analyze reports HIGH blocking for any non-exempt task requiring missing scope or current acceptance. Changed identities or failure paths require fresh protected acceptance. A confirmation line cannot define a seam.

## Deadline boundary

Before another unit or optional repeated expensive check, account for remaining time. Preserve unfinished required verification explicitly. Complete the in-flight unit safely and report actual overshoot after deadline; start nothing further. Resume outstanding work, then require final role and independent orchestrator build/test success before review. Budgets, append-only issue records and no-progress cap remain unchanged.

## Compatibility and evidence

Canonical output remains config-independent; per-user overrides preserve exact selections. Accepted plan Q2 preserves the shipped Claude Code, Codex and OpenCode mappings, including Claude Code's haiku standard model; documentation and tests must describe those mappings rather than silently changing them. No state schema migration or new command. Native scenario evidence names role inputs, observed output and git/CLI proof; generated text checks alone establish no behavioral pass.
